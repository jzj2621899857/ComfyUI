# ComfyUI Harness 源码改造规格说明

## 一、为什么需要改造 ComfyUI 源码

当前 ComfyUI 作为一个强大的生成式 AI 引擎，主要以"个人工具"的形式被使用。然而，要将其提升为工业级的 AI 内容生产系统，需要从源码层面进行深度改造。Harness Engineering 架构思想通过构建控制器、线束、仪表盘和安全网，实现对 AI 生成过程的标准化控制、调度与反馈。

**改造核心目标**：
- 将 ComfyUI 从"个人工具"转变为"工业级 AI 生产系统"
- 实现控制与执行分离，让 ComfyUI 成为纯粹的"推理执行器"
- 构建强反馈闭环，让生成质量评估实时反哺控制系统

## 二、源码改造概述

本项目将对 ComfyUI 源码进行深度改造，在其现有架构基础上嵌入 Harness Engineering 能力：

### 源码改造策略

| 原 ComfyUI 模块 | 改造方向 | 新增能力 |
|-----------------|---------|---------|
| `comfy/api/` | 扩展 API 层 | 新增 Harness API 网关，统一任务入口 |
| `comfy/model_management.py` | 嵌入模型管理 | 动态模型加载、模型仓库集成 |
| `comfy/execution.py` | 增强执行层 | 任务调度、状态追踪、进度上报 |
| `comfy/server.py` | 扩展服务层 | WebSocket 改进、反馈处理器集成 |
| `comfy/model_management.py` | 反馈增强 | 质量评估回调、异常检测 |

### 核心改造组件

1. **Harness API 网关**（新增）
   - RESTful API 端点 `/api/v1/generate`
   - 智能路由与负载均衡
   - 请求验证与认证
   - 挂载位置：`comfy/harness/api/`

2. **AI 编排器**（新增）
   - 动态工作流生成与拼装
   - 根据场景自动选择合适的生成策略
   - 支持文生图、图生图、ControlNet 引导等
   - 挂载位置：`comfy/harness/orchestrator/`

3. **任务状态管理器**（改造 `comfy/execution.py`）
   - 任务生命周期追踪（排队、生成中、后处理、失败）
   - Redis 持久化状态存储
   - WebSocket 实时进度推送
   - 全链路日志记录

4. **反馈处理器**（新增）
   - 质量评分分析
   - 错误日志聚合
   - 自动回滚机制
   - 挂载位置：`comfy/harness/feedback/`

5. **模型仓库服务**（改造 `comfy/model_management.py`）
   - 动态模型加载
   - 模型版本管理
   - LoRA 动态组装
   - 挂载位置：`comfy/harness/model_store/`

## 四、功能需求（源码级别）

### 4.1 Harness API 网关

#### 场景：接收生成请求
- **当** 客户端发送 POST `/api/v1/generate` 请求时
- **且** 请求包含有效的工作流参数
- **那么** 系统应返回任务 ID 并开始异步处理
- **实现位置**：`comfy/harness/api/routes.py`

#### 场景：查询任务状态
- **当** 客户端发送 GET `/api/v1/task/{task_id}` 请求时
- **那么** 系统应返回当前任务状态、进度百分比、预估剩余时间
- **实现位置**：`comfy/harness/state/manager.py`

#### 场景：取消任务
- **当** 客户端发送 DELETE `/api/v1/task/{task_id}` 请求时
- **那么** 系统应停止该任务的执行并清理相关资源
- **实现位置**：`comfy/execution.py` 改造 + `comfy/harness/state/manager.py`

### 4.2 AI 编排器（源码新增）

#### 场景：文生图流程编排
- **当** 用户请求不包含参考图时
- **那么** 编排器应生成带提示词增强的文生图工作流 JSON
- **实现位置**：`comfy/harness/orchestrator/workflow_gen.py`

#### 场景：图生图流程编排
- **当** 用户请求包含场景参考图时
- **那么** 编排器应生成带 ControlNet 引导的图生图工作流 JSON
- **实现位置**：`comfy/harness/orchestrator/workflow_gen.py`

#### 场景：动态 LoRA 选择
- **当** 用户指定了特定风格标签时
- **那么** 编排器应自动组装对应的 LoRA 模型组合
- **实现位置**：`comfy/harness/model_store/lora_manager.py`

### 4.3 任务状态追踪（源码改造）

#### 场景：任务状态追踪
- **当** 任务开始执行时
- **那么** 状态应更新为 `processing`，并记录开始时间
- **改造位置**：`comfy/execution.py` - 在 `execute.py` 函数中添加状态更新钩子

#### 场景：WebSocket 进度推送
- **当** 任务执行过程中产生进度更新时
- **那么** 系统应通过 WebSocket 向订阅客户端推送进度
- **改造位置**：`comfy/server.py` - 增强 WebSocket 处理逻辑

#### 场景：任务完成
- **当** 任务成功完成时
- **那么** 状态应更新为 `completed`，并存储生成结果路径
- **改造位置**：`comfy/execution.py` - 在任务完成回调中添加状态更新

### 4.4 模型仓库（源码改造）

#### 场景：工作流执行
- **当** 编排器下发工作流 JSON 时
- **那么** 执行器应解析并调用 ComfyUI 执行
- **改造位置**：`comfy/model_management.py` - 增强模型加载逻辑

#### 场景：模型动态加载
- **当** 工作流需要特定模型时
- **那么** 执行器应从模型仓库动态挂载所需模型
- **实现位置**：`comfy/harness/model_store/loader.py`

### 4.5 反馈处理器（源码新增）

#### 场景：质量评分
- **当** 任务完成后
- **那么** 反馈处理器应对输出结果进行自动化美学评分
- **实现位置**：`comfy/harness/feedback/evaluator.py`

#### 场景：异常检测
- **当** 某类任务失败率超过阈值时
- **那么** 系统应触发告警并可选择回滚到旧版工作流
- **实现位置**：`comfy/harness/feedback/detector.py` + `rollback.py`

## 五、技术选型

| 组件 | 技术方案 | 代码位置 |
|------|---------|---------|
| API 网关 | FastAPI (复用 ComfyUI 现有) | `comfy/harness/api/` |
| 状态存储 | Redis | `comfy/harness/state/` |
| 实时通信 | WebSocket (复用 ComfyUI 现有) | `comfy/server.py` 改造 |
| 任务队列 | 改造 `comfy/execution.py` | 集成 Celery/RQ |
| 模型存储 | S3/MinIO 或 NFS | `comfy/harness/model_store/` |
| 工作流引擎 | 改造 `comfy/execution.py` | 集成编排器 |

**重要原则**：所有改造必须保持向后兼容

- 原有的 API 端点必须继续工作
- 原有启动方式必须保持不变
- 原有的自定义节点必须继续可用
- 新增的 Harness 能力作为可选项存在

### 兼容性实现策略

```python
# comfy/harness/__init__.py

def setup_harness(app):
    if not HARNESS_ENABLED:
        return  # 原有行为
    
    # Harness 增强逻辑
    from .api.routes import router

    # 挂载新路由
```
